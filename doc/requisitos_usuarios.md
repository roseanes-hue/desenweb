# Levantamento de Requisitos de Usuários

**Criadora do Projeto:** Roseane Vilela de Sousa

---

## 1. Kit Pokémon

### 1.1 Requisitos de Usuário (RU)

| Código | Requisito de Usuário |
|---|---|
| **RU-PK-01** | O usuário deve poder pesquisar um Pokémon pelo nome (em inglês) ou pela ID nacional. |
| **RU-PK-02** | O usuário deve visualizar nome, ID, tipo(s), altura, peso e sprite oficial do Pokémon pesquisado. |
| **RU-PK-03** | O usuário deve ver barras das estatísticas de base (HP, Attack, Defense, Sp. Attack, Sp. Defense, Speed) e o total. |
| **RU-PK-04** | O usuário deve selecionar um tipo atacante e um ou dois tipos defensores e ver o multiplicador de dano calculado instantaneamente. |
| **RU-PK-05** | O usuário deve escolher montar o time de 6 Pokémon de forma 100% automática. |
| **RU-PK-06** | O usuário deve poder travar de 1 a 5 Pokémon de sua preferência e deixar que o sistema complete o restante do time. |
| **RU-PK-07** | O usuário deve poder filtrar a recomendação por um tipo foco (ex.: Fada ou Dragão). |
| **RU-PK-08** | O usuário deve visualizar um relatório explicativo dos pontos fortes e fracos do time gerado. |
| **RU-PK-09** | O usuário deve navegar entre Pokédex, Calculadora e Montador de Times sem perder o estado da aplicação. |

### 1.2 Origem dos Requisitos

Esses requisitos derivam do **Escopo do Projeto** (`escopo_projeto_kit_pokemon.md`) e do **Plano de Execução** (`plano_kit_pokemon.md`).

## 2. Sistema Acadêmico de Captura de Leads

### 2.1 Requisitos de Usuário (RU)

| Código | Requisito de Usuário |
|---|---|
| **RU-LE-01** | O usuário deve preencher um formulário com nome completo, e-mail, telefone (WhatsApp) e mensagem para solicitar informações sobre a instituição. |
| **RU-LE-02** | O usuário deve receber validação imediata dos campos (formato de e-mail e telefone) antes do envio. |
| **RU-LE-03** | O usuário deve ser informado, por uma notificação, se o cadastro do lead foi concluído com sucesso ou se houve erro. |
| **RU-LE-04** | O usuário administrativo deve visualizar a lista de leads cadastrados em tempo real, com os dados enviados pelo formulário. |
| **RU-LE-05** | O usuário administrativo deve acompanhar o status de atendimento de cada lead (novo, contatado, convertido ou perdido). |

### 2.2 Origem dos Requisitos

Esses requisitos derivam do **Plano de Execução** (`plano_sistema_leads.md`) e da documentação de referência legada (`plano_landingpage_nodejs.md`).

---

> **Observação:** Os requisitos de usuário descrevem o "o quê" do sistema (em linguagem do usuário). Os requisitos técnicos de sistema e funcionais/não-funcionais estão detalhados no **Escopo do Projeto** (`escopo_projeto_kit_pokemon.md`).
